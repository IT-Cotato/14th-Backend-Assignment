# 코테이토 스터디 매칭 플랫폼

- 이슈: #137
- 브랜치: `seonjae/monorepo` → `seonjae/basic`
- 범위: 인증(회원가입, 로그인, 로그아웃, 내 정보), 스터디 모집글, 댓글(= 스터디 신청)

## 배경

코테이토 스터디 신청은 네이버 카페에서 이뤄지고 있다. 기수와 파트를 글마다 직접 적어야 하고, 모집 마감 여부도 제목을 보고 판단해야 한다. 이번 작업은 코테이토 전용 플랫폼의 핵심 기능만 먼저 만든다.

- 가입할 때 기수와 파트를 받아 두고, 글과 댓글에 작성자 정보로 자동 표시한다.
- 모집글은 모집 상태(`RECRUITING`, `CLOSED`)를 가진다. 마감된 글에는 신청할 수 없다.
- 별도 신청 기능 없이 모집글에 댓글을 남기는 것이 곧 신청이다.

## 구조

- 모노레포로 전환했다. 기존 Spring Boot 코드는 `backend/`, 새 React 앱은 `frontend/`에 있다.
- 하네스 경로(`CLAUDE.md`, rules의 `paths`, 문서의 명령어)를 `backend/`, `frontend/` 기준으로 고쳤다.
- `.env`는 서버를 실행하는 `backend/`에서 읽는다. 키 이름은 `backend/.env.example`에 있다.

## 1. 인증

### 구현

| 구분 | 내용 |
| --- | --- |
| 회원가입 | 이메일 중복 확인 후 비밀번호를 BCrypt로 저장. 이메일은 소문자로 정규화 |
| 로그인 | 이메일과 비밀번호가 맞으면 JWT(HS512, 기본 1시간) 발급. 없는 이메일과 틀린 비밀번호는 같은 `USER-002` |
| 인증 필터 | `Authorization: Bearer` 토큰이 유효하고 로그아웃되지 않았으면 `userId`를 인증 정보로 등록 |
| 로그아웃 | 토큰의 SHA-256 해시를 `blacklisted_token`에 만료 시각과 함께 저장. 만료된 기록은 한 시간마다 삭제 |
| 내 정보 | 이메일, 이름, 닉네임, 기수, 파트. 비밀번호는 응답에 넣지 않음 |
| 프론트 | 회원가입(기수 숫자 입력, 파트 선택 목록), 로그인, 마이페이지, 로그인 상태별 헤더 |

### 설계 판단

- **로그아웃 토큰 저장 위치: DB.** 인메모리는 서버를 재시작하면 로그아웃한 토큰이 다시 살아난다. 토큰 원문 대신 해시를 저장해 DB가 유출돼도 토큰을 쓸 수 없게 했다.
- **무효 토큰은 익명으로 통과.** 필터에서 바로 401을 내면 만료된 토큰을 가진 사용자가 공개 목록도 못 본다. 그래서 익명으로 넘기고, 로그인이 필요한 API에서만 `JsonAuthenticationEntryPoint`가 401(`COMMON-004`)을 공통 에러 형식으로 내려준다.
- **프론트 401 처리.** 토큰을 들고 보낸 요청이 401이면 토큰을 지우고 로그인 화면으로 보낸다. 로그인 실패(토큰 없이 보낸 401)는 제외해서 에러 메시지가 그대로 보이게 했다.
- **화면 이동과 상태 해제는 같은 transition에서.** React Router의 이동은 transition으로 처리된다. 로그인 상태 해제를 따로 반영하면 마이페이지의 `RequireAuth`가 먼저 리다이렉트해서 "로그아웃했어요" 대신 "로그인이 필요한 화면이에요"가 보였다. E2E에서 발견해 수정했다.
- **검증 메시지는 사용자에게 보여줄 문장으로.** `INVALID_INPUT`의 `message`에 첫 번째 필드 오류를 그대로 담는다. (예: `기수는 1 이상의 정수로 입력해 주세요.`) 파트에 목록 밖 값이 오면 JSON 변환 단계에서 막혀 같은 `COMMON-003`이 된다.

## 2. 스터디 모집글

### 구현

| 구분 | 내용 |
| --- | --- |
| 작성 | 제목 1~50자, 내용 1~2000자. 처음 상태는 `RECRUITING` |
| 목록 | 키워드(제목, 내용), 모집 상태, 작성자 파트를 함께 걸 수 있음. 최신순, 페이징 |
| 상세 | 작성자 본인이면 `isAuthor: true` |
| 수정 | 보낸 필드만 변경(PATCH). 모집 상태는 `RECRUITING` ↔ `CLOSED` 자유롭게 |
| 삭제 | 댓글을 먼저 지우고 글을 삭제 (한 트랜잭션) |
| 프론트 | 목록(검색 폼, 필터, 페이지 이동, 조건은 URL 쿼리에 유지), 상세, 작성/수정. 작성자에게만 수정·마감·삭제 버튼 |

### 설계 판단

- **검색은 JPQL 하나로.** 조건 값이 `null`이면 그 조건을 건너뛰는 `(:x is null or ...)` 형태다. 작성자 파트로 거르기 위해 `User`를 조인하고, 같은 조인을 fetch join으로 써서 작성자 정보 N+1을 막았다.
- **댓글 수는 페이지 단위로 한 번에.** 글마다 count를 부르지 않고 현재 페이지 글 id로 `group by` 한 번을 실행한다. 엔티티에 댓글 수 컬럼을 두면 동시성 처리가 필요해져서 이번 범위에서는 뺐다.
- **`%`, `_` 이스케이프.** 키워드의 `%`, `_`를 글자 그대로 찾도록 `!`로 이스케이프한다. MySQL에서 `\`는 문자열 이스케이프와 겹쳐서 `!`를 골랐다.
- **권한 위치.** 공개/로그인 구분은 `SecurityConfig`의 URL 규칙, 작성자 확인은 서비스의 `isWrittenBy`에서 한다. 화면에서 버튼을 숨기는 것과 별개로 서버가 403을 내린다.

| --- | --- | --- |
| 5 | `POST /api/study-posts` | 로그인 |
| 6 | `GET /api/study-posts?keyword&status&part&page&size` | 공개 |

## 3. 댓글(스터디 신청)

### 구현

| 구분 | 내용 |
| --- | --- |
| 작성 | 1~500자. 마감된 글이면 `409 STUDY-003`. 같은 사람이 여러 번 써도 됨 |
| 목록 | 오래된 순, 페이지 크기 기본 20. 내 댓글이면 `isAuthor: true` |
| 수정·삭제 | 작성자만. 글 작성자도 남의 신청 댓글은 바꿀 수 없음 |
| 프론트 | 상세 화면 아래 신청 댓글 목록과 입력창, 내 댓글의 수정(인라인)·삭제. 비로그인은 로그인 안내, 마감 글은 신청 불가 안내 |

### 설계 판단

- 마감 여부는 댓글 작성 시점에 서버에서 확인한다. 화면에서 입력창을 숨겨도 API를 직접 부르면 409가 나온다.
- 댓글을 바꾸면 목록의 댓글 수가 달라지므로 모집글 목록 캐시도 함께 무효화한다.

### API

| # | API | 권한 |
| --- | --- | --- |
| 10 | `POST /api/study-posts/{postId}/comments` | 로그인 |
| 11 | `GET /api/study-posts/{postId}/comments` | 공개 |
| 12 | `PATCH /api/comments/{commentId}` | 작성자 |
| 13 | `DELETE /api/comments/{commentId}` | 작성자 |

## ERD

`users` 1:N `study_post`, `study_post` 1:N `study_post_comment`, `users` 1:N `study_post_comment`.
명세 외로 로그아웃 토큰을 저장하는 `blacklisted_token(id, token_hash UK, expires_at)`을 추가했다. 자세한 내용은 `docs/erd/`.

## 남은 점

- 리프레시 토큰이 없어 1시간마다 다시 로그인해야 한다.
- 모집 인원, 신청 승인/거절 같은 기능은 이번 범위에 없다.
- 테스트 프레임워크 Mockito는 Windows 한글 사용자 경로에서 에이전트 attach가 실패해 subclass mock maker를 쓴다. final 클래스는 mock할 수 없다.
