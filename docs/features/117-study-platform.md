# 기능 문서

코테이토 14기 스터디 매칭 플랫폼에서 구현한 기능을 화면, API, 규칙, 검증 방법 기준으로 정리한 문서예요.
요청·응답 형식은 [api-spec.md](../api-spec.md), 폴더 구조는 [project-structure.md](../project-structure.md)를 참고해요.

> 핵심 개념: **모집글에 댓글을 남기는 것이 곧 스터디 신청**이에요.

---

## 1. 회원가입 · 로그인 · 로그아웃 · 내 정보

### 회원가입 (`/signup`, `POST /api/auth/signup`)
- 입력: 이메일, 비밀번호(8자 이상), 비밀번호 확인, 이름, 닉네임(2~10자), 기수(1 이상), 파트(PM·DE·BE·FE)
- 화면에서 먼저 검증하고, 서버도 같은 규칙을 Bean Validation으로 검증해요. (실패 시 400 `COMMON-003`)
- 이미 가입한 이메일은 409 `USER-001`이고, 서버 메시지를 화면에 보여줘요.
- 비밀번호는 BCrypt로 암호화해서 저장하고, 어떤 응답에도 포함하지 않아요.
- 가입하면 로그인 화면으로 이동하고 "회원가입이 완료됐어요." 안내를 보여줘요.

### 로그인 (`/login`, `POST /api/auth/login`)
- 성공하면 HS256 JWT(`accessToken`, 1시간 유효)를 받아 `localStorage`에 저장하고, `GET /api/users/me`로 사용자 정보를 불러와요.
- 이메일 또는 비밀번호가 틀리면 401 `USER-002` 메시지를 보여줘요. (어느 쪽이 틀렸는지 알려주지 않아요)
- 보호 페이지에서 로그인 화면으로 왔다면 로그인 후 원래 페이지로 돌아가요.
- 새로고침해도 저장된 토큰으로 로그인 상태를 복원해요.

### 인증 처리 (프론트엔드)
- Axios 인터셉터가 모든 요청에 `Authorization: Bearer <JWT>`를 붙여요.
- 401을 받으면 토큰을 지우고 로그인 화면으로 보내요. 공개 GET 요청은 만료된 토큰 때문에 막히지 않도록 토큰 없이 한 번 다시 보내요.
- `RequireAuth`가 `/studies/new`, `/studies/:id/edit`, `/mypage`를 보호해요.

### 로그아웃 (`POST /api/auth/logout`)
- 서버는 토큰의 SHA-256 해시를 `revoked_token` 테이블에 만료 시각과 함께 저장하고, 이후 같은 토큰은 401로 거부해요. JWT 원문은 저장하지 않아요.
- 프론트엔드는 **서버가 무효화를 확인했을 때만** 로그아웃 성공으로 처리해요.

| 서버 결과 | 처리 |
| --- | --- |
| 204 | 토큰 삭제 → `/login` 이동, "로그아웃했어요." |
| 401 (이미 무효화·만료된 토큰) | 토큰 삭제 → `/login` 이동, "이미 만료되어 로그아웃 상태로 전환했어요." |
| 500·네트워크 오류 | 성공으로 표시하지 않고 로그인 상태와 토큰을 유지해요. 마이페이지에서 **로그아웃 다시 시도** 또는 **이 기기에서만 로그아웃**을 고를 수 있어요. 후자를 고르면 "서버 무효화는 확인하지 못해 토큰이 만료 시각까지 유효할 수 있다"고 안내해요. |

### 마이페이지 (`/mypage`, `GET /api/users/me`)
- 로그인 사용자만 들어올 수 있고, 들어올 때마다 API를 다시 호출해 이름·이메일·닉네임·기수·파트를 보여줘요.
- 로딩·오류(다시 시도) 상태와 로그아웃 버튼이 있어요. 헤더의 "마이페이지" 링크로 이동해요.

## 2. 스터디 모집글

### 목록 (`/studies`, `GET /api/study-posts`)
- 최신순, 10개씩 페이지네이션. 상태 배지, 제목, 작성자(닉네임·기수·파트), 댓글 수, 작성일을 보여줘요.
- 키워드(제목·내용), 모집 상태(RECRUITING·CLOSED), 작성자 파트 필터를 함께 쓸 수 있어요. 조건이 여러 개면 모두 만족하는 글만 보여요.
- 검색 조건과 페이지는 URL 쿼리에 저장돼서 새로고침·뒤로 가기에도 유지돼요. 필터를 바꾸면 첫 페이지로 돌아가요.
- 빈 목록, 조건에 맞는 글 없음, 범위를 벗어난 페이지, 오류 상태를 각각 안내해요.

### 상세 (`/studies/:id`, `GET /api/study-posts/{postId}`)
- 비로그인 사용자도 볼 수 있어요. 본문 줄바꿈을 유지하고, 수정된 글은 수정 시각을 함께 보여줘요.
- 서버가 돌려주는 `isAuthor`가 true일 때만 수정·삭제 버튼을 보여줘요.
- 없는 글은 "존재하지 않는 모집글이에요."(404)를 보여줘요.

### 작성 (`/studies/new`, `POST /api/study-posts`)
- 로그인 필요. 제목 1~50자, 내용 1~2000자이고 글자 수를 표시해요. 처음 상태는 RECRUITING이에요.
- 작성하면 상세 페이지로 이동해요.

### 수정 (`/studies/:id/edit`, `PATCH /api/study-posts/{postId}`)
- 작성자만 들어올 수 있어요. 다른 사용자는 "수정 권한이 없어요." 화면을 보고, 서버도 403 `STUDY-002`로 막아요.
- 바뀐 필드만 보내요. 모집 상태를 **CLOSED(모집 마감)**로 바꿀 수 있어요.

### 삭제 (`DELETE /api/study-posts/{postId}`)
- 작성자만, 확인 창을 거쳐 삭제해요. 삭제하면 댓글도 함께 지워지고 목록으로 이동해요.

## 3. 댓글 (스터디 신청)

상세 페이지 아래 **"스터디 신청 댓글"** 영역이에요.

| 기능 | API | 규칙 |
| --- | --- | --- |
| 목록 | `GET /api/study-posts/{postId}/comments?page=0&size=20` | 공개. 오래된 순, 20개씩 페이지네이션. 작성자 닉네임·기수·파트·작성일 표시 |
| 작성 | `POST /api/study-posts/{postId}/comments` | 로그인 필요. 1~500자(앞뒤 공백 제외). 작성하면 새 댓글이 있는 마지막 페이지로 이동 |
| 수정 | `PATCH /api/comments/{commentId}` | 작성자 본인만. 그 자리에서 수정, 1~500자 검증 |
| 삭제 | `DELETE /api/comments/{commentId}` | 작성자 본인만. 확인 창, 삭제 후 목록 갱신(마지막 페이지가 비면 앞 페이지로 이동) |

- **내 댓글**에만 "내 댓글" 표시와 수정·삭제 버튼이 보여요. 모집글 작성자도 남의 댓글은 수정·삭제할 수 없어요. (서버 403 `COMMENT-002`)
- 비로그인 사용자에게는 작성 폼 대신 "로그인하고 신청하기" 버튼을 보여주고, 로그인 후 같은 글로 돌아와요.
- **모집 마감(CLOSED)** 글에는 작성 폼 대신 "모집이 마감된 스터디라 댓글을 작성할 수 없어요."를 보여줘요. 화면을 연 뒤 마감되어 서버가 409 `STUDY-003`을 돌려줘도 같은 안내로 바꾸고 새로고침을 권해요.
- 오류 처리: 401 → 로그인 화면, 403 → 권한 안내, 404 → 삭제된 글·댓글 안내 후 목록 갱신, 409 → 마감 안내.
- 로딩, 빈 목록, 오류(다시 시도) 상태를 각각 처리해요.

## 4. 공통 응답 · 오류 형식

- 성공: `{ success, status, data, timestamp }`. 프론트엔드는 항상 `data`를 꺼내 써요. 204는 본문이 없어요.
- 실패: `{ success, status, code, message, method, path, timestamp }`. 화면에는 서버의 `message`를 보여주고, 상황별로 더 구체적인 안내로 바꿔요.
- 오류 코드 전체 목록은 [api-spec.md 7장](../api-spec.md#7-에러-코드)을 참고해요.

## 5. 화면 반응형

- Tailwind CSS로 모바일과 PC를 함께 지원해요. 헤더 메뉴는 좁은 화면에서 줄바꿈되고, 필터와 버튼은 세로로 쌓여요.
- 띄어쓰기 없는 긴 제목·본문·댓글도 카드 안에서 줄바꿈돼요.
- 375×812 화면에서 가로 스크롤, 화면 밖 요소, 버튼 겹침, 글자 잘림이 없는지 Playwright로 자동 점검해요. (`frontend/e2e/mobile.spec.ts`)

## 6. 검증 방법

| 종류 | 위치 | 내용 |
| --- | --- | --- |
| 백엔드 테스트 | `backend/src/test` | 컨트롤러 검증, 서비스 규칙, 인증·로그아웃 통합 테스트 |
| 브라우저 E2E | `frontend/e2e` | 실제 백엔드와 실제 브라우저(Chromium)로 회원가입·로그인, 모집글, 댓글, 마이페이지·로그아웃, 로그아웃 실패, 모바일 레이아웃을 검증 |
| 스크린샷 | `docs/screenshots/` | 회원가입, 로그인, 목록, 상세, 작성, 수정, 댓글 작성 완료, 마이페이지 |

### E2E 테스트 데이터
- E2E는 고정된 테스트 계정 풀(`e2e.pool.<파트><번호>@example.com`)을 재사용해요. 처음 실행할 때만 가입하고 이후에는 로그인만 해요.
- 회원가입 화면 테스트만 실행마다 새 계정(`e2e.<id>@example.com`)을 하나 만들어요.
- 테스트가 만든 모집글만 테스트가 끝날 때 삭제해요. 댓글은 모집글과 함께 지워져요.
- 계정 삭제 API는 없어서 테스트 계정은 DB에 남아요.
