## 배경

코테이토의 스터디 신청은 네이버 카페에서 이뤄지고 있다. 이를 개선하기 위해 코테이토 회원이 스터디 모집글을 올리고 댓글로 신청할 수 있는 전용 플랫폼을 만들며, 그중 핵심 기능인 인증, 모집글, 댓글부터 구현한다.

## 구현 내용

구조는 `docs/project-structure.md`, API 상세는 `docs/api-spec.md`, 테이블은 `docs/erd/README.md`를 본다.

- **모노레포 전환**: 기존 백엔드를 `backend/`로 옮기고 `frontend/`(React)를 새로 만들었다. 하네스와 문서의 경로·명령어도 이에 맞게 고쳤다.
- **인증**: 회원가입(기수·파트 포함), 로그인(JWT), 로그아웃, 내 정보. 프론트는 로그인·회원가입·마이페이지와 로그인 상태에 따라 바뀌는 헤더, 로그인하지 않은 접근을 막는 보호 라우트가 있다.
- **모집글**: 작성, 목록(검색어·모집 상태·파트 필터, 페이징), 상세, 수정, 삭제. 수정·삭제는 작성자만 할 수 있다. 검색 조건은 URL 쿼리에 담아 새로고침해도 유지된다.
- **댓글(스터디 신청)**: 작성, 목록, 수정, 삭제. 마감된 글에는 작성할 수 없고, 수정·삭제는 댓글 작성자만 할 수 있다.
- **E2E 테스트**: Playwright로 인증, 모집글, 댓글의 정상·에러 시나리오를 검증한다.
- 공통: 요청은 `Controller → Service → Repository`로 흐르고, Entity 대신 DTO를 응답한다. 성공·실패·목록 응답 형식을 통일했다.

## API 명세

| 기능 | API | 로그인 |
|---|---|---|
| 인증 | `POST /api/auth/signup`, `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/users/me` | 로그아웃·내 정보만 필요 |
| 모집글 | `POST` `GET` `/api/study-posts`, `GET` `PATCH` `DELETE` `/api/study-posts/{postId}` | 조회는 불필요, 나머지는 필요 |
| 댓글 | `POST` `GET` `/api/study-posts/{postId}/comments`, `PATCH` `DELETE` `/api/comments/{commentId}` | 조회는 불필요, 나머지는 필요 |

주요 에러: 400 `COMMON-003`(입력 검증), 401 `USER-002`(로그인 실패)·`COMMON-004`(토큰 없음·무효·로그아웃), 403 `STUDY-002`·`COMMENT-002`(작성자 아님), 404 `STUDY-001`·`COMMENT-001`, 409 `USER-001`(이메일 중복)·`STUDY-003`(마감된 글에 댓글). 요청·응답 예시는 `docs/api-spec.md`에 있다.

## 설계 결정

- **로그아웃한 토큰은 DB 테이블(`revoked_token`)에 저장한다.** JWT는 서버가 취소할 수 없어서, 토큰마다 고유한 `jti`와 만료 시각을 저장하고 필터가 요청마다 확인한다. 메모리 저장(재시작하면 사라짐)보다 단순하고 오래 유지돼서 택했다. 운영이라면 TTL이 있는 Redis가 더 알맞다.
- **인증 실패는 401로 직접 응답한다.** Spring 기본은 403이라 "로그인 필요"와 "권한 없음"을 구분할 수 없다. 프론트도 로그인 실패(`USER-002`)와 토큰 만료가 둘 다 401이라, 상태 코드가 아니라 `code`(`COMMON-004`)로 구분한다.
- **목록 쿼리는 N+1을 피한다.** 작성자는 `join fetch`로, 댓글 수는 `group by` 쿼리 한 번으로 가져온다. 검색어의 `%`, `_`는 이스케이프해서 와일드카드로 동작하지 않게 했다.
- **글 삭제는 댓글을 벌크 쿼리로 먼저 지운 뒤 글을 지운다.** 댓글이 글을 참조(FK)하므로 순서가 바뀌면 실패한다.
- **작성자 여부(`isAuthor`)는 서버가 계산해 내려준다.** 프론트는 이 값으로 수정·삭제 버튼을 보여주고, 버튼을 숨겨도 서버가 한 번 더 막는다(E2E에서 API를 직접 호출해 403으로 확인).

## 남은 이슈

- Swagger UI의 Authorize 버튼 조작은 화면에서 직접 확인하지 못했다. (API는 `curl`과 E2E로 확인)
- 만료된 `revoked_token` 행은 로그아웃할 때만 정리한다. 운영이라면 Redis TTL이나 주기적 정리가 필요하다.
- 토큰을 `localStorage`에 저장해서 XSS에 노출될 수 있다. 이번 범위에서는 감수했고, HttpOnly 쿠키가 대안이다.
- `npm audit`이 기존 `vite` 계열에 high 5개를 경고한다. 고치려면 vite 메이저 버전을 바꿔야 해서 제외했다.
- 개발 DB에 검증용(`verify-*`)·E2E(`e2e-`) 계정이 남아 있다.
