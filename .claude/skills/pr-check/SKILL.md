# PR 제출 전 점검

## 목적과 범위

제출할 변경사항을 점검하고 근거와 함께 결과를 보고한다.
파일과 Git 상태는 변경하지 않는다.
단, 검증에 따른 빌드 산출물·캐시 생성은 허용한다.

## 절차

### 1. 점검 기준 확인

- `CLAUDE.md`, `docs/conventions.md`, 변경 파일에 해당하는 Rules를 확인한다.
- 구조를 대조할 때는 `docs/project-structure.md`를 참고한다.
- 사용자가 제공한 요구사항·완료 조건·PR 대상 브랜치를 확인한다.
- 제출 범위를 결정할 정보가 없으면 필요한 내용만 질문한다.
- 특정 주차·이슈·브랜치나 제공되지 않은 요구사항을 임의로 가정하지 않는다.

### 2. 제출 범위와 내용 확인

다음 명령을 참고해 커밋된 변경, 스테이징·미스테이징 변경,
미추적 파일을 구분한다. 마지막 커밋만으로 전체 PR을 판단하지 않는다.

- `git status --short --branch`
- `git log <base>..HEAD --oneline`
- `git diff --name-status <base>...HEAD`
- `git diff --name-status HEAD`
- `git diff --cached --name-status`

`<base>`는 확인된 PR 대상 브랜치로 바꾼다.
대상 참조가 없으면 비교를 미확인으로 기록한다.
원격 최신 상태를 확인하지 않았다면 로컬 참조 기준임을 밝힌다.

파일 목록에서 민감파일을 먼저 식별한 뒤, 일반 파일의 diff와
필요한 코드 문맥을 읽는다. 미추적 파일은 별도로 확인한다.
스테이징된 실제 내용도 읽어 빈 파일이나 최신 내용 누락을 확인한다.

### 3. 관련 항목 점검

변경에 해당하는 항목만 확인한다.

- 요구사항·완료 조건 충족 여부와 목적 밖의 변경
- 적용할 프로젝트 규칙 준수 여부
- 문서의 사실관계·참조 경로와 실제 코드의 일치 여부
- API의 요청·응답·예외·Swagger 설명 간 일치 여부
- 설정·의존성 변경의 이유와 영향 범위
- 민감파일·빌드 산출물·개인 IDE 설정의 제출 포함 여부
- 현재 브랜치와 PR 대상의 적절성

Rules·Skill·Hook은 경로, 연결 설정, 지시 충돌도 확인한다.
파일 존재나 정적 검토만으로 자동 적용·호출·차단을 확인했다고 판단하지 않는다.

### 4. 필요한 검증 수행

검증을 선택한 이유를 짧게 설명하고 다음 기준을 따른다.

| 변경 유형 | 검증 |
|---|---|
| 문서 | 사실관계·경로·누락·충돌 확인. 빌드는 일괄 실행하지 않음 |
| Java 코드 | 관련 테스트와 필요한 컴파일·빌드 |
| API | 정상 요청과 주요 실패 사례의 테스트 또는 HTTP 호출 |
| 설정·의존성 | 영향받는 빌드·실행 경로 |
| Rules·Skill·Hook | 정적 검토와 실제 적용·호출·동작 확인을 구분 |

Windows PowerShell에서는 프로젝트 루트의 Gradle Wrapper를 사용한다.
빌드·테스트는 `.\gradlew.bat build`, 테스트만 할 때는 `.\gradlew.bat test`를 사용한다.
`build`에 테스트가 포함되므로 이유 없이 같은 검증을 반복하지 않는다.

기존 결과는 대상 코드와 실행 조건이 현재에도 유효한지 확인한 뒤 활용한다.
사용자가 제공한 결과와 직접 실행한 결과를 구분한다.
Hook은 안전한 테스트 입력으로 차단·허용을 확인한다.
환경이 없거나 Claude Code·IDE 확인이 필요하면 미확인 이유와 확인 방법을 남기고,
사용자에게 필요한 확인만 요청한다.

### 5. 결과 보고

한국어로 다음 순서에 맞춰 보고한다.

1. **점검 범위**: 현재·대상 브랜치, 비교 기준, 변경 범위, 참고한 요구사항·규칙
2. **발견한 문제**: 중요한 문제부터 파일 경로·근거·영향·권장 조치 제시.
   확정된 문제와 추가 확인 사항을 구분
3. **검증 결과**: 아래 표로 기록. 관련 없는 검사는 제외하고 필요하면 이유 설명
4. **남은 작업**: 수정·추가 검증·사용자 확인·미커밋 변경의 반영 필요 사항

| 항목 | 상태 | 근거 또는 미확인 이유 |
|---|---|---|
| 실제 점검 항목 | 통과 / 실패 / 미확인 | 실행 결과와 확인한 내용 |

빌드·서버 시작·DB 연결·Swagger 접속·개별 API 동작은 구분한다.
문제가 없어도 점검 범위를 넘어 정확성을 보장하지 않는다.
필수 조건에 실패·미확인이 남으면 제출 준비 완료로 단정하지 않고 보고 후 종료한다.

## 하지 말 것

- 파일 수정, 스테이징, 커밋, push, PR 생성, 머지를 수행하지 않는다.
- `.env` 등 민감파일의 내용을 출력하거나 실제 비밀번호·토큰을 노출하지 않는다.
  해당 파일은 경로와 확인 필요 사항만 보고한다.
- DB 변경 API 호출이나 위험한 명령을 검증 목적으로 임의 실행하지 않는다.
- 실행하지 않았거나 확인하지 못한 검증을 통과했다고 보고하지 않는다.
