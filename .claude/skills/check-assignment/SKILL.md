# 과제 제출 점검

1. 연결할 이슈와 과제 안내를 읽고 이번 제출의 요구사항을 정리한다. 주차별 브랜치와 산출물을 이전 과제에서 그대로 추정하지 않는다.
2. `git status --short`, `git branch --show-current`, `git diff <base>...HEAD`, 커밋 전 변경분을 확인한다. base가 개인 누적 브랜치인지 확인한다.
3. 하네스 과제에서는 CLAUDE.md 200줄 이하, docs 2개 이상, rules 2개 이상과 조건부 paths, 스킬의 description, settings.json의 훅 연결을 확인한다.
4. stage 예정 파일에 비밀 파일·빌드 산출물·개인 설정이 없는지 파일명으로 확인한다. 비밀 값을 읽어서 검사하지 않는다.
5. `docs/development.md`의 빌드·테스트와 훅 테스트를 실행한다. DB 연결과 Swagger는 실행 결과가 있을 때만 완료로 표시한다.
6. 결과를 `통과 / 미확인 / 수정 필요`로 나누고 근거를 적는다. PR은 과제 안내의 개요, 작업 내용, 기대 효과, 관련 이슈, 리뷰 포인트 형식으로 작성한다.

이 스킬은 점검과 본문 작성까지 수행한다. push와 PR 생성은 사용자가 요청한 범위에서 진행하고, 병합은 하지 않는다.
