# Git 협업 규칙

## 작업 전

- 현재 브랜치와 커밋하지 않은 변경사항을 확인한다.
- 사용자가 작업 중인 변경을 임의로 삭제하거나 되돌리지 않는다.
- 개인 누적 브랜치는 `영문이름/basic`을 사용한다.
- 새 작업 브랜치는 개인 누적 브랜치에서 분기한다.
- 구체적인 작업 브랜치명은 해당 작업의 안내를 따른다.

## 커밋

- 커밋 메시지는 `타입: 작업 내용` 형식으로 작성한다.
- 타입은 `feat`, `fix`, `docs`, `style`, `refactor`, `chore` 중 작업 성격에 맞게 선택한다.
- 커밋 전 스테이징된 변경 내용을 확인한다.
- `.env`, 실제 비밀번호·토큰, 빌드 산출물, 개인 IDE 설정을 커밋하지 않는다.
- 요청받지 않은 커밋·push·PR 생성·머지를 임의로 수행하지 않는다.

## PR

- 작업 브랜치에서 개인 누적 브랜치로 PR을 제출한다.
- 제출 전에 base와 compare 브랜치를 확인한다.
- PR 본문은 해당 작업의 제출 형식이 있으면 이를 우선 따른다.
- 변경 내용과 이유, 실제 검증 결과, 미확인 사항을 구분해 작성한다.
- 이슈를 해결하는 PR은 `closes #이슈번호`로 연결한다.
- 머지는 파트장이 진행한다.

## 금지

- `main`과 `develop`에 직접 push하지 않는다.
- 강제 push를 사용하지 않는다.
- 기존 작업을 잃을 수 있는 명령을 임의로 실행하지 않는다.

상세한 커밋 타입과 협업 기준은 `docs/conventions.md`를 참고한다.
