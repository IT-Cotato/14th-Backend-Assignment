# 코딩 규칙

## 기본 원칙

- Java 21 및 Spring Boot 4.1.1 환경을 기준으로 개발한다.
- 기존 코드의 구조와 네이밍 방식을 우선적으로 따른다.
- 요청받은 작업과 무관한 코드는 수정하지 않는다.
- 중복 코드를 줄이되 불필요한 추상화는 지양한다.

## 패키지 구성

- 도메인별 코드는 `domain/{도메인명}/`에 배치한다.
- 공통 기능은 기존 `global/` 패키지 구조를 참고한다.
- 코드 배치가 불명확하면 `docs/architecture.md`를 확인한다.

## API 구현

- 기존 공통 응답 구조를 유지한다.
- 성공 응답은 `ResponseUtils` 사용을 우선 고려한다.
- 비즈니스 예외는 `Backend14thException`과 `ErrorCode`를 활용한다.
- 자세한 API 규칙은 `docs/api-conventions.md`를 따른다.

## 코드 변경

- 기존 동작에 영향을 줄 수 있는 변경은 먼저 영향 범위를 확인한다.
- 새로운 의존성을 추가하기 전에 필요성을 설명한다.
- 작업 완료 후 변경사항과 검증 결과를 보고한다.
