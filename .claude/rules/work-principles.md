# 작업 원칙

## 응답

- 한국어로 답한다.
- 코드를 수정하기 전에 무엇을 왜 바꾸는지 먼저 한두 줄로 설명한다.
- 확실하지 않은 내용은 추측해서 단정하지 않는다. 모르면 모른다고 말한다.

## 범위

- 요청받은 파일만 수정한다. 관련 있어 보여도 요청 밖의 파일은 건드리지 않는다.
- 파일이나 패키지를 새로 만들거나 삭제하기 전에 먼저 알리고 확인을 받는다.
- 기존 코드를 전면 재작성하지 않는다. 필요한 부분만 고친다.

## 에러 처리

- 에러가 나면 스택트레이스의 마지막 `Caused by:`까지 확인한 뒤 원인을 설명한다.
  상위 예외만 보고 추측하지 않는다.
- 원인이 불확실하면 가능성을 나열하고, 어떻게 확인하면 되는지 알려준다.
- 라이브러리 버전 변경을 해결책으로 제안하지 않는다.

## 검증

- 코드를 수정한 뒤에는 빌드가 되는지 확인할 방법을 함께 알려준다.
- "아마 될 것이다"로 끝내지 않는다. 확인하지 않은 것은 확인하지 않았다고 말한다.
