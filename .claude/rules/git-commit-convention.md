# 커밋 메시지 규칙

- 커밋 메시지는 `type: 설명` 형식을 따른다. (예: `feat: 책 등록 API 추가`, `fix: null 체크 누락 수정`)
- type은 `feat`, `fix`, `refactor`, `docs`, `test`, `chore` 중 하나를 사용한다.
- 설명은 한글로, 명령형 대신 평서형으로 간결하게 작성한다.
- 하나의 커밋에는 하나의 논리적 변경만 담는다. (기능 추가 + 포맷팅 같이 섞지 않기)
- 커밋 전 `git status`로 의도하지 않은 파일(.env, build 산출물 등)이 포함되지 않았는지 확인한다.
