# E2E 테스트 작성 규칙

Playwright로 화면 → 프론트 → API → DB 전체 흐름을 검증한다.

## 요소 찾기

- 요소는 `getByRole`, `getByLabel`, `getByText`로 찾는다. CSS 선택자와 `data-testid`에 기대지 않는다.
- 찾을 수 없으면 테스트를 고치기 전에 화면 쪽 접근성(label 연결, button, 링크)이 맞는지 먼저 확인한다.

## 기다림

- `waitForTimeout` 같은 고정 대기를 쓰지 않는다.
- `expect(...)`가 조건이 맞을 때까지 기다리는 것을 이용한다. 이동 확인은 `toHaveURL`, 화면 변화는 `toBeVisible` 등을 쓴다.

## 데이터와 독립성

- 테스트는 서로 독립이다. 앞선 테스트가 만든 데이터에 기대지 않고, 필요한 데이터는 해당 테스트 안에서 만든다.
- 이메일, 닉네임, 글 제목은 매번 새로 만든다. 같은 DB를 쓰므로 테스트 계정의 이메일은 `e2e-`로 시작하고 고유값(UUID 등)을 붙인다.
- 테스트 계정의 비밀번호를 코드에 적지 않는다. 실행할 때 만들거나 환경변수로 받는다.
- 준비 단계(가입, 글 작성 등)는 API 호출로 만들고, 검증하려는 화면 조작만 브라우저로 한다.

## 시나리오

- 기능마다 정상 케이스 1개 이상, 에러 케이스 1개 이상을 둔다.
- 화면에서 숨겨진 동작(남의 글 수정·삭제 등)은 API를 직접 호출해 403·409 같은 서버 응답도 확인한다.
- 실패한 테스트를 통과시키려고 테스트를 지우거나 검사를 약하게 바꾸지 않는다. 원인이 앱인지 테스트인지 먼저 가린다.

## 실행과 보고

- 백엔드(8080)를 먼저 실행한다. 프론트 서버는 `playwright.config.ts`의 `webServer`가 띄운다.
- 테스트가 같은 DB를 쓰므로 `workers: 1`, `fullyParallel: false`를 유지한다.
- 결과는 실제 실행해서 나온 `N passed` 숫자로만 보고한다. 캡처와 로그에 토큰·비밀번호가 보이지 않게 한다.
