# 002. .env 훅이 커밋/PR 초안 속 글자를 막았고, 커밋 메시지 안 명령 치환은 통과시켰다

- 날짜: 2026-11-05
- 관련 파일: `.claude/hooks/block-env-access.sh`, `.claude/hooks/test-block-env-access.sh`
- 001과 같은 종류(문자열 기반 훅이 데이터를 명령으로 오인)의 반복이다.

## AI가 틀린 것

### 1) 오탐: 초안 본문의 `.env` 글자를 막음
- `cat > .local/claude/commits/x.md <<'EOF' ... EOF`로 커밋 초안을 저장할 때 본문의 `.env` 글자 때문에 막혔다.
- `gh pr create --body "... .env ..."`도 막혔다. 처음 버전은 `git commit -m`만 예외로 뒀다.
- AI는 훅을 고치지 않고 초안 표현을 "환경변수 파일"로 바꿔서 피해 갔다. 훅의 문제를 사용자 문서 쪽에서 덮은 셈이다.
- 재현 명령을 Bash에 직접 쓰다가 그 명령 자체가 다시 훅에 막혔다.

### 2) 구멍: `git commit -m "$(cat .env)"`가 통과
- 오탐을 줄이려고 `-m` 인자를 통째로 지웠는데, 안에 있는 `$(...)`도 같이 지워져서 실행되는 명령을 검사하지 못했다.

## 고친 방법
1. 데이터로 보는 범위를 정했다: `git commit -m/--message`, `gh pr|issue create|edit|comment`의 `--title/--body`, `cat`/`tee`로 넘기는 heredoc 본문.
2. 그 안에 `$(`나 백틱이 있으면 지우지 않고 검사한다. heredoc은 구분자를 따옴표로 감쌌으면(`'EOF'`) 본문이 펼쳐지지 않으므로 데이터로 본다.
3. heredoc 줄에 `|`가 있으면(`cat <<'EOF' | bash`) 본문이 실행될 수 있어서 지우지 않는다.
4. 차단 메시지에 "글자만 쓰려면 Write/Edit 도구를 쓰라"는 안내를 넣었다. 파일 도구 훅은 경로만 검사한다.
5. 테스트를 차단 12개, 통과 9개 더 늘렸다(총 91개). 훅 사본을 일부러 망가뜨려서(명령 치환 검사 제거, heredoc 제거 무효화) 테스트가 각각 4개, 6개 FAIL로 회귀를 잡는 것을 확인했다.
6. 실제 세션에서 heredoc 초안 저장은 통과하고, `git commit --dry-run -m "$(cat <없는 경로>/.env)"`는 막히는 것을 확인했다.

## 교훈
- 훅이 정상 작업을 막으면 우회하지 말고 훅을 고친다. 그리고 그 케이스를 테스트에 추가한다.
- 오탐을 줄이려고 무언가를 "지울" 때는, 지우는 부분 안에 실행되는 코드가 있을 수 있는지 먼저 본다. 오탐 수정이 새로운 구멍이 되기 쉽다.
- 훅을 시험하는 케이스는 Bash에 직접 쓰지 말고 파일(테스트 스크립트)로 실행한다.

## 남은 한계
- `echo ".env" >> .gitignore`처럼 echo/printf로 쓰는 글자는 여전히 막힌다. 파일 내용 작성은 Write/Edit 도구를 쓴다.
- `cat > x.sh <<'EOF'`로 스크립트를 만든 뒤 `bash x.sh`로 실행하는 우회는 못 막는다.
